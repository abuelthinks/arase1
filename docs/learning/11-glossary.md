# Lesson 11: Plain-English Glossary

Not something to read front to back. It's a **dictionary to come back to** whenever a word in
the code makes your eyes glaze over. Each entry: what it means, and where to see a real one
in ARASE.

Sections: **ARASE words → Web basics → Frontend → Backend → Background & live → Running & deploying**

---

## ARASE words

**SPED**: Special Education. The whole domain of the app.

**IEP (Individualized Education Program)**: The main document ARASE produces for each
student, written with AI from the assessments. Stored as a `GeneratedDocument` with
`document_type='IEP'`. Generated by `api/tasks.py` → `iep_service.run_iep_generation`.

**Role**: One of `ADMIN`, `TEACHER`, `SPECIALIST`, `PARENT`. Stored on `User.role`. Decides
almost everything a user can see or do.

**Student status**: Where a student is in the process: `PENDING_ASSESSMENT →
ASSESSMENT_SCHEDULED → ASSESSED → ENROLLED ↔ INTEGRATED → ARCHIVED`. "Integrated" = in a
mainstream classroom with support.

**Team / StudentAccess**: The staff and parent attached to a student. Each member is one
`StudentAccess` row. **No row = can't see the student.**

**Report cycle**: One reporting period for a student (`ReportCycle`). Forms, trackers, and
documents belong to a cycle.

**Assessment vs. tracker**: *Assessments* happen once at the start (parent, multidisciplinary
/specialist, SPED/teacher). *Trackers* are filled in every cycle to measure progress.

**Section / contribution**: The specialist assessment is shared. Each specialist fills their
own **section**, stored as a `SectionContribution`. Sections can be submitted, reopened,
locked, and unlocked.

**`form_data` / `translated_data`**: The JSON column holding a form's answers, and its
English translation (filled in by a background job).

**Activity event**: A record that "something happened" (`ActivityEvent`), like
`STUDENT_CREATED` or `REPORT_READY`. Creating one also pushes a live message to the right
browsers.

## Web basics

**Client / server**: The *client* asks (the browser running Next.js). The *server* answers
(Django).

**HTTP request / response**: One round trip. Request: "GET me student 5's profile."
Response: the data plus a status code.

**Method (verb)**: The kind of request. **GET** read, **POST** create/do, **PATCH/PUT** update,
**DELETE** remove. Django view methods match: `def get(...)`, `def post(...)`.

**Endpoint / route**: An address the backend answers at, like `/api/students/5/profile/`.
Listed in `api/urls.py` and `backend/urls.py`.

**JSON**: The text format data travels in: `{"first_name": "Sam", "grade": "3"}`.

**Status code**: The 3-digit verdict. 200 OK, 201 Created, 202 Accepted (queued), 400 Bad
Request, 401 not logged in, 403 not allowed, 404 not found, 429 too many requests, 500
crashed, 503 unavailable. (Lesson 07 has the full table.)

**Header**: Extra info on a request/response: content type, cookies, `X-CSRFToken`.

**Payload / body**: The data sent with a request, like `{ email, password }`.

**Cookie**: A small value the browser stores and sends back automatically to the site that
set it. ARASE keeps login tokens in cookies.

**First-party vs. third-party cookie**: First-party = set by the site you're on.
Third-party = set by a *different* site. Incognito and Safari block third-party cookies. That
broke login once (Lesson 09, Case 2).

**SameSite**: A cookie setting that controls whether it's sent on cross-site requests.
`Lax` locally, `None` (+ `Secure`) in production.

**CORS**: The browser rule that a page from site A can only read responses from site B if B
says it's allowed. Configured with `CORS_ALLOWED_ORIGINS` in the settings.

**Redirect (301/302)**: The server saying "go to this other URL instead." A *loop* of these is
a classic rewrite bug.

**Trailing slash**: The `/` at the end of `/api/students/`. ARASE's URLs all have one.
Django's `APPEND_SLASH` redirects URLs missing it, which caused Lesson 09 Case 1.

**CRUD**: Create, Read, Update, Delete: the four basic data operations.

## Frontend

**Next.js**: The React framework the frontend is built on.

**App Router**: Next.js's rule that **folders under `src/app/` are URLs** and `page.tsx` is
the screen. `[id]` captures part of the URL.

**React**: The library for building screens out of components. Core idea: describe what the
screen looks like *for the current data*; React updates it when the data changes.

**Component**: A function that returns a piece of screen (JSX). Always functional components
here (team rule).

**JSX**: The HTML-looking code in a component's `return (...)`. `{value}` inserts a value;
`cond && <Thing/>` shows `<Thing/>` only when `cond` is true.

**Props**: Inputs passed to a component, like function arguments: `<Badge color="red" />`.

**State**: A component's changeable data, made with `useState`. Changing it redraws the
screen.

**Hook**: A function starting with `use…` that gives a component a capability: `useState`,
`useEffect`, `useParams`, `useAuth`, `useRealtimeRefresh`. Custom ones live in `hooks/`.

**`useEffect`**: "Run this after the screen draws, and again when these values change."
Where pages fetch data.

**`useCallback` / `useMemo`**: Keep a function or value from being recreated on every
redraw. You can mostly read past them. Focus on what's inside.

**`useRef`**: A box that holds a value *without* causing a redraw when it changes. Used for
things like the open WebSocket in `RealtimeProvider`.

**Context / Provider**: React's way to share one value with the whole app. `<AuthProvider>`
supplies it; `useAuth()` reads it.

**`"use client"`**: First line of a file that runs in the browser. Needed for state, effects,
and clicks.

**Query string / search params**: The `?a=1&b=2` part of a URL. Read with
`useSearchParams()`. The workspace uses these heavily to pick what to show.

**TypeScript / type / interface**: JavaScript plus descriptions of data shapes
(`email: string`). They catch mistakes before running. `ProfileData` at the top of the student
page is free documentation of what the backend sends.

**Axios**: The library for calling the backend. Configured once in `lib/api.ts` as `api`.
Team rule: never raw `fetch` for the backend.

**Interceptor**: Axios code that runs on every request or response. Ours add the CSRF header
and handle 401s.

**Rewrite (proxy)**: A Next.js rule (`next.config.ts`) that quietly forwards `/api/*` from the
Vercel site to Railway. The browser thinks it's talking to one site.

**Sonner / toast**: The pop-up messages. `toast.success(...)`, `toast.error(...)`.

**Tailwind**: Styling with class names like `flex gap-2 text-muted`. Colors come from tokens
defined in `globals.css` and mapped in `tailwind.config.js`.

**Lint (ESLint)**: A tool that reads your code and flags likely mistakes. `npm run lint`.

**Build**: Turning the source into what actually runs (`npm run build`). Catches TypeScript
errors. If it fails on Vercel, the deploy fails.

## Backend

**Django**: The Python web framework the backend is built on.

**Django REST Framework (DRF)**: The add-on for JSON APIs: `APIView`, `ViewSet`,
serializers, permissions, throttling.

**View**: The code that handles one endpoint. `APIView` (you write `get`/`post`) or `ViewSet`
(a whole resource).

**ViewSet / ModelViewSet**: A view for list/create/retrieve/update/delete at once.
`StudentViewSet`. Wired up by a **router**.

**Router**: Makes a family of URLs from one line: `router.register(r'students', StudentViewSet)`.

**`get_queryset`**: The ViewSet method that decides **which rows this user may see**. Most
"can't see it" bugs end here.

**Base class / inheritance**: `class AssessmentSectionWriteView(SectionWriteView)` means
"everything `SectionWriteView` does, plus changes." If a view looks empty, read its parent.

**Serializer**: Translates between database rows and JSON. `fields = [...]` decides exactly
what the frontend sees.

**SerializerMethodField**: A computed field. Its value comes from a `get_<name>` method.

**`read_only_fields`**: Fields the frontend can see but not change.

**Model / field**: A model is a table (`Student`); fields are columns (`CharField`,
`DateField`, `JSONField`, `ForeignKey`…).

**ForeignKey / related_name**: A link to a row in another table, and the name for going
backwards. `related_name='assigned_users'` lets you write `student.assigned_users`.

**`__` (double underscore) in queries**: "Follow this relationship" or "use this operator."
`assigned_users__user=me`, `status__in=[...]`, `email__iexact=...`.

**ORM / QuerySet / `.objects`**: Python instead of SQL. `Student.objects.filter(...)`. Any
`.objects` line touches the database.

**N+1 queries**: Loading a list (1 query), then running another query for *each* item
(N queries). `SerializerMethodField`s can cause it. Shows up as slow list pages.

**Migration**: A recorded change to the database structure, in `api/migrations/`. Made with
`makemigrations`, applied with `migrate`. A new model field does nothing until both run.

**Signal**: "When X happens, also do Y." `post_save.connect(trigger_translation_task, ...)` at
the bottom of `models.py` queues a translation every time a form is saved.

**Middleware**: Code that runs on every request before/after the view (security, CORS).

**`permission_classes`**: The gate on a view. `[IsAuthenticated]` = must be logged in. Role
checks inside the method add finer rules.

**`request.user` / `request.data`**: The logged-in user (from the cookie) / the JSON body
they sent.

**Authentication vs. authorization**: *Who are you?* (401 when it fails) vs. *are you
allowed?* (403).

**JWT**: A signed token proving who you are. Short-lived **access** token + longer
**refresh** token, both in cookies here.

**SimpleJWT**: The library that makes and checks those tokens.

**HttpOnly cookie**: A cookie JavaScript can't read, so scripts can't steal it.

**CSRF / CSRF token**: Protection against other sites forging requests with your cookies.
The frontend sends `X-CSRFToken` on writes; the backend checks it (`enforce_csrf`).
"403 CSRF Failed" = they didn't match.

**Throttle / rate limit**: A cap on requests per minute (600/user in production). Over it
→ 429.

**Service**: A Python module in `api/services/` holding business logic. Views call services.

**Management command**: A custom `python manage.py <name>` command, in
`api/management/commands/` (e.g. `reconcile_assessment_workflow`).

**Django shell**: `python manage.py shell`. A Python prompt with your models loaded, for
looking at data directly.

**Traceback**: The list of calls that led to a crash. Read it bottom-up.

## Background & live updates

**Celery**: A separate program (the **worker**) that runs slow jobs from a queue. Tasks
are in `api/tasks.py`.

**Task**: A function marked `@shared_task` that Celery can run. `generate_iep_task`,
`translate_form_data_task`.

**`.delay(...)`**: "Queue this task with these arguments and return immediately." Doesn't
run it right there.

**Task id / `AsyncResult`**: The ticket number for a queued job, and how the backend asks
Celery about it. `TaskStatusView` → `/api/tasks/<id>/status/`.

**Retry**: `self.retry(exc=exc)` in a task: try again later (up to `max_retries`).

**Polling**: The frontend asking "done yet?" on a timer. `pollTaskStatus` every 3 seconds.

**Redis**: A fast in-memory store. Here: Celery's job queue, and the channel layer in
production.

**Broker**: The queue Celery reads jobs from. Redis, set by `CELERY_BROKER_URL`.

**Result backend**: Where Celery stores finished results. Here the database (`django-db`),
so the web server can read what the worker returned.

**WebSocket**: A connection that stays open so the server can push messages to the browser.
Used for live refresh, the notification bell, and shared form editing.

**Django Channels**: The library that adds WebSockets to Django.

**Consumer**: The WebSocket version of a view, in `api/consumers.py`.
(`RealtimeConsumer`, `NotificationConsumer`, `CollaborationConsumer`.)

**Channel layer / group**: How a message gets from wherever it was created to the right open
sockets. Sockets join **groups** (`realtime_admins`, `realtime_user_7`); the server sends to a
group. In-memory locally (one program only) unless `REDIS_URL` is set; Redis in production.

**Refresh target**: A label like `dashboard`, `student`, `reports` attached to a live
message. `useRealtimeRefresh({ targets: [...] })` refetches only when one matches.

**WS ticket**: A 60-second token from `/api/auth/ws-ticket/`, passed as `?token=` when
opening a socket, because sockets can't use the proxied cookie.

## Running & deploying

**Virtualenv (`venv/`)**: An isolated Python install with this project's packages.

**ASGI / WSGI**: How a Python web server runs Django. WSGI = plain HTTP only. ASGI = also
WebSockets. ARASE uses ASGI (`backend/asgi.py`).

**daphne**: The ASGI server used locally. Doesn't reload on code changes.

**gunicorn + uvicorn**: The ASGI server setup used in production (`railway.json`).

**Settings (`base` / `dev` / `prod`)**: Shared config plus per-environment overrides.
`DJANGO_SETTINGS_MODULE` picks one; it defaults to `dev`.

**Environment variable / `.env`**: Settings and secrets kept outside the code. `.env` locally
(never committed), dashboards in production.

**`NEXT_PUBLIC_`**: Frontend env vars the browser can see. Baked in at build time:
changing one needs a redeploy.

**`DEBUG`**: On locally (detailed error pages), off in production (generic errors).

**`ALLOWED_HOSTS`**: The domain names Django will answer to. Others get 400.

**Healthcheck**: A URL (`/api/health/`) the host pings to decide if a deploy is alive.

**Vercel / Railway**: Where the frontend / backend run live.

**S3 / django-storages**: Cloud file storage in production (`USE_S3=True`). Locally, files
go to `media/`.

**Gemini / Ollama / `AI_PROVIDER`**: The AI. Gemini = Google's cloud model. Ollama = a local
model. `auto` = Gemini first, Ollama as backup. Logic in `api/services/llm_service.py`.

**Mailpit / smstrap**: Local stand-ins that catch emails / SMS so you can read them without
sending anything real.

**BOM (byte order mark)**: An invisible character some Windows tools put at the start of a
file. Breaks tools that don't expect it (Lesson 09, Case 5).
