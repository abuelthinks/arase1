# ARASE

A web app for managing SPED (Special Education) students — from initial assessment through enrollment, monthly progress tracking, and AI-assisted IEP/report generation.

## Stack

| Layer | Tech |
|---|---|
| Frontend | Next.js 16, React 19, TypeScript, Tailwind CSS, Axios, Sonner |
| Backend | Django 6, Django REST Framework, SimpleJWT |
| Real-time | Django Channels + Daphne (ASGI), Redis channel layer |
| Background jobs | Celery + Redis |
| AI | Google Gemini (`gemini-2.5-flash-lite`) |
| Storage | AWS S3 (prod) / local filesystem (dev) |
| Database | PostgreSQL (prod) / SQLite (dev) |
| Email | SMTP (prod) / Mailpit (dev) |
| SMS | Twilio or Vonage (prod) / smstrap or console (dev) |
| Deployment | Railway (backend) + Vercel (frontend) |

## Local Development

### Prerequisites

- Python 3.11+
- Node.js 18+
- Redis (optional — needed for Celery and WebSockets)
- [Mailpit](https://mailpit.axllent.org/) (optional — for viewing emails locally)
- [smstrap](https://github.com/axllent/smstrap) (optional — for viewing SMS codes locally)

### 1. Backend

```bash
# Create and activate a virtual environment
python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate

# Install dependencies
pip install -r backend/requirements.txt

# Copy environment file and fill in values
cp .env.example .env
```

Minimum `.env` for local dev:

```
SECRET_KEY=<generate with: python -c "from django.core.management.utils import get_random_secret_key; print(get_random_secret_key())">
GEMINI_API_KEY=your-gemini-api-key
USE_S3=False
```

```bash
# Run migrations
python manage.py migrate --settings=backend.settings.dev

# Create an admin user
python manage.py createsuperuser --settings=backend.settings.dev

# Start the dev server
python manage.py runserver --settings=backend.settings.dev
```

API available at `http://localhost:8000/api/`.

### 2. Frontend

```bash
cd frontend
npm install
npm run dev
```

Frontend available at `http://localhost:3000`.

### 3. Redis + Celery (optional)

Required for AI-assisted document generation and real-time collaborative form editing.

```bash
# Start Redis
redis-server

# Start Celery worker (separate terminal)
celery -A backend worker --loglevel=info
```

Without these, the app is fully usable — AI generation tasks queue silently and fail, real-time collaboration falls back gracefully.

### 4. Mailpit (optional)

```bash
mailpit
```

Invitation emails appear at `http://localhost:8025`.

## Architecture

### User Roles

| Role | Description |
|---|---|
| `ADMIN` | Full access — manages users, students, cycles, document generation |
| `TEACHER` | Assigned to students; submits SPED progress trackers |
| `SPECIALIST` | Assigned to students by specialty; fills sections of multidisciplinary forms |
| `PARENT` | Completes parent assessment and parent tracker for their assigned child |

Users are created via invitation links (email-based, 72-hour expiry, single-use). There is no public sign-up.

### Student Lifecycle

```
PENDING_ASSESSMENT
      ↓  admin requests assessment
ASSESSMENT_SCHEDULED
      ↓  admin marks assessed
ASSESSED
      ↓  admin enrolls
ENROLLED  ←→  INTEGRATED
      ↓  admin archives
ARCHIVED
```

Progress trackers can only be submitted for students in `ENROLLED` or `INTEGRATED` status.

### Multi-Specialist Forms

The multidisciplinary assessment and multidisciplinary tracker are collaborative forms split into sections by specialty (Speech, OT, PT, etc.). Each specialist fills only their assigned section(s). Sections are soft-locked while being edited (Redis-backed, released on save or timeout). Admins can reopen submitted sections.

### Document Generation

IEPs and monthly reports are generated by Google Gemini via Celery background tasks. Admin triggers generation from the dashboard; a task ID is returned immediately and polled for completion. Generated PDFs are stored in S3 (prod) or `media/` (dev).

### Authentication

- JWT stored in HttpOnly cookies (`access_token`, `refresh_token`)
- Refresh tokens rotate on use and are blacklisted after rotation
- Cookie-auth mutations require a valid CSRF token
- All document download endpoints require authentication

## Environment Variables

See [`.env.example`](.env.example) for a full annotated reference.

| Variable | Required | Description |
|---|---|---|
| `SECRET_KEY` | Yes | Django secret key |
| `GEMINI_API_KEY` | Yes | Google Gemini API key |
| `USE_S3` | No | `True` for S3 storage; defaults to `False` (local filesystem) |
| `DATABASE_URL` | Prod only | PostgreSQL connection string |
| `REDIS_URL` | Prod only | Redis connection string |
| `FRONTEND_URL` | Prod only | Full URL of the frontend (CORS + invite emails) |
| `SMS_BACKEND` | No | `console` (default), `smstrap`, `twilio`, or `vonage` |
| `AWS_*` | Prod only | S3 credentials — only read when `USE_S3=True` |
| `TWILIO_*` / `VONAGE_*` | Prod only | SMS credentials |

## Deployment

### Backend (Railway)

1. Set all production environment variables in Railway
2. Set `DJANGO_SETTINGS_MODULE=backend.settings.prod`
3. Run command: `python manage.py migrate && daphne -b 0.0.0.0 -p $PORT backend.asgi:application`

### Frontend (Vercel)

1. Set root directory to `frontend/`
2. Set `NEXT_PUBLIC_API_URL` to your Railway backend URL
3. Deploy

### Required production environment variables

```
SECRET_KEY
GEMINI_API_KEY
DATABASE_URL
REDIS_URL
USE_S3=True
AWS_ACCESS_KEY_ID
AWS_SECRET_ACCESS_KEY
AWS_STORAGE_BUCKET_NAME
FRONTEND_URL
CORS_ALLOWED_ORIGINS
CSRF_TRUSTED_ORIGINS
ALLOWED_HOSTS
SMS_BACKEND=twilio
TWILIO_ACCOUNT_SID
TWILIO_AUTH_TOKEN
TWILIO_FROM_PHONE
```
